# packages/

Un package ROS 2 par fonction, à plat.

| Package | Arrivé | Rôle |
|---|---|---|
| `theatre_contrats` | L1a (02/11) | le contrat commun : noms de topics (relatifs), clés de payload, organes, codec StringTime, profils QoS — Python pur, voir son README |
| `theatre_interfaces` | L1a (02/11), renommé en L1e-3b (07/11) | les messages (`StringTime`…) — copie UNIQUE (les copies vision/télécommande sont supprimées) ; ex `robot_interfaces` (dossier, `package.xml`, `project()`, imports, scripts CLI, compose, Ansible ; noms de messages inchangés), l'ancien nom est effacé des Pi par `packages_retires` — voir son README |
| `didier_bringup`, `didier_description`, `didier_drive`, `didier_rehearsal`, `didier_sim`, `didier_web` | L1e-1 (06/11), renommés en L1e-2 (07/11) | les 6 packages ROS autonomes du robot (launch du Pi, URDF, chaîne cmd_vel, sim Gazebo, salle de répétition, console web), déménagés de `legacy/dadou_robot_ros/conf/` (L1e-1) puis renommés `robot_*` → `didier_*` (L1e-2 : dossier, package, module Python, share ; topics, nœuds, exécutables et fichiers inchangés — ⚠️ `robot_description` reste le nom STANDARD ROS du paramètre/topic de l'URDF). Compose/Dockerfiles les montent par `packages/<nom>` ; Ansible les pousse par la liste `packages` de l'hôte robot (`hosts`) et efface des Pi les anciens `robot_*` (`packages_retires`, vars/main.yml) |
| `dadou_utils_ros` | L1e-3a (07/11) | la lib partagée du parc (série/WebSocket/LoRa, fichiers JSON, LCD, journalisation), déménagée de `legacy/dadou_utils_ros/` — nom inchangé, disparaît à L5 ; remplace les 3 liens symboliques des dépôts legacy ; `conf/`, `docs/`, `scripts/` restent dans `legacy/dadou_utils_ros/` (`ansible/` → `deploy/` et `jenkins/` supprimé au L1e-4a) — voir son README |
| `didier_core` | L1e-3c (07/11) | le **cœur** du robot (servos, roues, LED, audio, animations, regard, suivi ; `robot_config.py`, `robot_static.py`), ex-package `robot` de `legacy/dadou_robot_ros/robot/` — forme ament vraie, exécutables de même nom (`wheels_node`, `animations_node`…). Ses DONNÉES (`json/`, `medias/`, `db/`, `conf/`) restent dans `legacy/dadou_robot_ros/` (conteneurs : `/home/ros2_ws/src/robot/`), racine lue dans `DIDIER_DATA_DIR` ; Ansible efface l'ancienne forme des Pi (`chemins_retires_robot`) — voir son README |
| `didier_vision` | L1e-3d (08/11) | le **cerveau perceptif** du Pi vision (suivi de personne, conversation temps réel, metteur en scène intérieur, heartbeat), ex-package `vision` de `legacy/dadou_vision_ros/vision/` — forme ament vraie, exécutables de même nom (`vision_status`, `person_tracker`, `chat`, `reflection`), launch `vision.launch.py` dans le package. Ses DONNÉES (`conf/`, `medias/`, `db/`, `models/`) restent dans `legacy/dadou_vision_ros/`, racine lue dans `DIDIER_VISION_DATA_DIR` — voir son README |
| `didier_jeu` | A1 (02/11) | le sélecteur de jeu (arbre py_trees + score), **SIM-ONLY** : `jeu_node` refuse de démarrer hors domaine 43 ; monté/copié par la sim seulement — voir son README. Ansible ne le pousse sur aucun Pi (L1e-1 : listes `packages` explicites par machine, `hosts`) |

**Catalogue + version (lot L1c, 04/11)** : `theatre_contrats.topics.CATALOGUE` (`catalogue`) et `DEPLOY_SHA` (`deploy_sha`), StringTime latchés publiés par `catalogue_node` (package `didier_web`) ; inventaire gravé dans `test_inventaire.py` / `test_topics_relatifs.py`. Détail : `docs/interfaces.md` et `packages/didier_web/README.md`.

**Namespace (lot L1b, 04/11)** : tout nœud de ces packages tourne sous `/<ROBOT_NAME>/` (défaut `/didier/`), posé par les launch (`GroupAction` + `PushRosNamespace` absolu) ou, pour un `ros2 run`, par `--ros-args -r __ns:=/didier`. Conséquence pour le code : **noms de topics relatifs, toujours** (`theatre_contrats.topics` le grave) ; seuls `/clock`, `/tf`, `/tf_static`, `/rosout`, `/parameter_events` restent globaux. Un nouveau launch doit suivre le même gabarit — `packages/didier_core/test/unit/test_namespace_contract.py` le vérifie (inventaire gravé des launch : en ajouter un exige de l'y inscrire).

Les autres packages sont encore dans `legacy/` (télécommande : `legacy/dadou_control_ros/controller`, réécrite en L4).

**Tout conteneur qui exécute du code du parc doit avoir `dadou_utils_ros` ET `theatre_contrats` dans son `src/`** (le shim `utils_static.py` de la lib importe le contrat) : les compose et Dockerfiles de `legacy/` montent/copient ces packages depuis ici (contextes de build nommés). Ansible les rsync vers `ros2_ws/src/` de chaque Pi (rôle `synchronise` : liste `packages` de l'hôte, à défaut `packages_default` = `theatre_contrats`, `theatre_interfaces`, `dadou_utils_ros`, depuis L1e-3a/3b ; l'ancienne copie embarquée `src/<projet>/dadou_utils_ros` est effacée par `chemins_retires_lib`). La sentinelle `colcon build` est posée par Ansible à chaque déploiement (lot « Ansible nickel », 07/11 ; `sentinelle_build` de l'hôte — robot : `src/didier_core/change` depuis L1e-3c).
